`laminara-server` — это и демон, и клиент к нему. Одни команды управляют самим процессом, другие выполняются внутри запущенного сервера.

## Управление процессом

| Команда | Что делает |
| --- | --- |
| `start --config <путь>` | Запускает сервер в текущем терминале. Демонизируют его systemd или Docker. |
| `status [--json]` | Состояние запущенного сервера. |
| `stop` | Останавливает сервер. |
| `console [--nerd]` | Полноэкранная [интерактивная консоль](/console): живые логи, мастера сборок и прогресс. `--nerd` включает иконки Nerd Font. |
| `logs [-f] [--level ..] [--source ..] [--backscroll N]` | Поток логов. `-f` — следить дальше, `--backscroll` — сколько строк истории показать сразу. |
| `exec "<команда>"` | Выполняет одну команду сервера и выходит. Код возврата пробрасывается — удобно для скриптов. |
| `hash [--algo argon2id] [пароль]` | Хеширует пароль для файла аккаунтов (читает stdin, если аргумент не задан). |
| `client-config --config <путь> --endpoint <адрес>` | Печатает конфигурацию, которую запекают в лаунчер: адреса, кольцо ключей подписи, соль отпечатка, оформление. |
| `nginx-config --config <путь> --domain <домен проекта> [--no-tls]` | Печатает конфиг nginx под этот сервер: порт слушателя и путь к хранилищу берутся из конфига. `--no-tls` — один блок на `:80` для первого запуска, пока certbot не выписал сертификат. |

`console`, `status`, `logs` и `exec` подключаются к работающему демону через Unix-сокет.

## Команды сервера

Выполняются в `console` или через `exec`. Список для обоих один — команды живут в едином реестре.

<ParamField path="versions [запрос]">
  Список версий Minecraft. Необязательный запрос фильтрует вывод: `versions 1.21`.
</ParamField>

<ParamField path="loaders <версия>">
  Загрузчики, доступные для версии Minecraft, и их актуальные версии.
</ParamField>

<ParamField path="install <имя> <версия> [loader=..] [loaderVersion=..] [platform=..] [java=..]">
  Собирает клиент в папку профиля. Аргументы разобраны в разделе [Подготовка сборок](/builds/preparing). Алиас: `prepare`.
</ParamField>

<ParamField path="publish <имя>">
  Публикует собранный профиль: составляет и подписывает манифест.
</ParamField>

<ParamField path="builds">
  Список собранных и опубликованных клиентов с их статусом.
</ParamField>

<ParamField path="build <имя>">
  Всё об одной сборке: версия Minecraft и загрузчик, Java, размер, платформы, дата публикации,
  адрес сервера с онлайном и правила доступа. Алиас: `info`.
</ParamField>

<ParamField path="players">
  Кто сейчас в игре на серверах сборок: онлайн, вместимость и имена. Адрес берётся из
  `serverAddress` сборки. Алиасы: `online`, `who`.
</ParamField>

<ParamField path="delete <имя>">
  Удаляет сборку (папку профиля и опубликованный манифест). Алиасы: `deletebuild`, `remove`.
</ParamField>

<ParamField path="auth test <логин> <пароль>">
  Проверяет пару логин/пароль через настроенный адаптер. `auth validate <токен>` проверяет токен доступа. Удобно для отладки раздела `auth`.
</ParamField>

<ParamField path="access rules · access check <сборка> <ник> · access reload">
  Показывает действующие правила доступа, объясняет решение по конкретному игроку и
  сбрасывает кэш источников. Подробнее — [Доступ к сборкам](/builds/access).
</ParamField>

<ParamField path="hwid · machines · ban · bans">
  Узнавание машин и блокировки: `hwid` показывает настройки, `machines <ник>` — машины
  игрока, `ban <ник> <причина>` банит, `bans` перечисляет и снимает. Подробнее —
  [Машины и баны](/server/machines).
</ParamField>

<ParamField path="signing keys · signing new <путь>">
  Показывает кольцо подписи и создаёт следующий ключ. Порядок смены —
  [Ключ подписи](/server/signing).
</ParamField>

<ParamField path="settings · settings <раздел> · settings <путь> [значение]">
  Настройки проекта: без аргументов — разделы, с разделом — его поля и списки, с путём —
  одна настройка с подсказкой и вариантами. `settings <путь> <значение>` меняет и сразу
  записывает файл настроек, `settings clear <путь>` возвращает значение по умолчанию,
  `settings add <список> [имя]` и `settings remove <путь>` правят списки (правила доступа,
  списки допущенных, настройки модулей). Алиас: `config`.
</ParamField>

<ParamField path="restart">
  Перезапускает проект на месте — с новыми настройками. Процесс остаётся тем же, systemd и
  docker перезапуск не замечают, консоль подключается сама.
</ParamField>

<ParamField path="status · version · help">
  Состояние сервера, его версия и список всех команд.
</ParamField>
