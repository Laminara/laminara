Сборка лаунчера

Лаунчер принадлежит одному проекту: адрес сервера, ключи подписи, соль машинного отпечатка и оформление записываются в файл при сборке. Игрок ничего не настраивает и адрес не вводит, а чужой проект через этот файл не откроется.

Одной командой

Сервер делает лаунчер сам — ни Rust, ни Node, ни компилятора на нём не нужно. Он берёт готовый лаунчер из релиза Laminara и впечатывает в него вашу конфигурацию: адрес, ключи, соль, оформление и иконку.

  1. Укажите адрес, по которому придут игроки

    Осторожно

    Это адрес у игрока, а не адрес слушателя: 127.0.0.1 годится только для проверки на самом сервере. Адресов можно указать несколько — лаунчер возьмёт самый быстрый из отвечающих и переключится на запасной, если основной умрёт.

  2. Соберите и выпустите

    Команда скачивает заготовки под Windows, Linux и macOS (проверяя их контрольные суммы), впечатывает конфигурацию, ставит вашу иконку из branding.logoPath и сразу публикует версию. Имя файла — из оформления: при branding.windowTitle = «Magic World» получится Magic World.exe. Версию можно назвать явно: launcher build 1.3.0.

    Иконка ставится в двух местах, и оба важны: в ресурсах .exe — её показывает проводник, — и самим лаунчером при запуске окна, откуда её берут панель задач и переключение окон. Второе работает на всех системах, поэтому на Linux и macOS окно тоже с вашим логотипом.

  3. Выложите игрокам

    Сервер раздаёт опубликованный лаунчер сам, по постоянному адресу:

    Эта ссылка определяет систему по браузеру и отдаёт нужный файл — её и давайте игрокам. Если нужна ссылка на конкретную систему, она такая же предсказуемая:

    Адрес не меняется никогда: после каждой пересборки по нему автоматически лежит свежий файл. Скачивание не требует входа — игроку нужно попасть в лаунчер до того, как он сможет войти. Файл приходит под своим именем из оформления (Magic World.exe), самодостаточный: скачал и запустил, установка не нужна. Дальше лаунчер обновляет себя сам.

    Сами файлы по-прежнему лежат в launcher/<версия>/, если их нужно выложить куда-то ещё.

После обновления сервера лаунчер перепекается и выпускается заново — так до игроков доедет свежая версия. Отключается это настройкой launcher.autoBake.

Лаунчер для macOS

Под macOS лаунчер — это .app, а не один файл, поэтому он приезжает архивом Ваш Лаунчер-mac-os-arm64.app.tar.gz. Внутри обычное приложение: имя, иконка из вашего оформления и настройки проекта лежат рядом с программой, а не внутри неё.

Так сделано ради подписи. Начиная с Apple Silicon система отказывается запускать изменённую программу, а «впечатать» конфигурацию — это как раз изменить файл. Поэтому сервер кладёт настройки рядом с программой, внутрь .app, и не трогает сам исполняемый файл: подпись, которую поставила Apple при сборке, остаётся целой.

Процессор при скачивании выбирать не нужно: внутри одна программа сразу под Apple Silicon и Intel. Ссылки /launcher/mac-os-arm64 и /launcher/mac-os отдают одно и то же, а /launcher сам определит мак по браузеру.

Первый запуск у игрока

У пакета, собранного сервером, нет печати целостности: сервер кладёт внутрь ваши настройки, а запечатать .app умеет только сам мак — команда codesign есть лишь в macOS. Поэтому скачанное из браузера приложение система при первом запуске не откроет, и «правой кнопкой → Открыть» тут не поможет: для macOS пакет выглядит не как «неизвестный разработчик», а как испорченный. После неё приложение запускается обычным двойным щелчком, и повторять это не нужно — в том числе после самообновления лаунчера.

Заметка

Пакет, собранный на маке через build-launcher.sh --target macos, печать получает: скрипт подписывает его командой codesign сразу после сборки. Такому приложению хватает «правой кнопкой → Открыть» — терминал игроку не нужен. Совсем без предупреждений работает только приложение, заверенное у Apple (notarization): нужна платная подписка Apple Developer и мак, на котором заверяется каждая версия.

Микрофон и голосовой чат

Моды вроде Simple Voice Chat просят микрофон не у игры, а у приложения, из которого она запущена, — то есть у лаунчера. macOS пускает такой запрос, только если в приложении есть сразу две вещи: строка-объяснение NSMicrophoneUsageDescription в Info.plist и разрешение com.apple.security.device.audio-input в подписи. Нет хотя бы одной — система не показывает окно с вопросом, а снимает процесс; мод в этом случае пишет, что лаунчер не поддерживает разрешения на микрофон.

В лаунчере Laminara есть обе: строку кладёт в пакет сервер, разрешение вшито в подпись при сборке релиза. От игрока нужно одно — разрешить микрофон в окне, которое покажет macOS при первом запуске голосового чата. Разрешение выдаётся лаунчеру, игра работает под ним.

Если игрок случайно нажал «Не разрешать», починить можно в «Системных настройках» → «Конфиденциальность и безопасность» → «Микрофон»: там надо включить ваш лаунчер. После обновления лаунчера macOS может спросить про микрофон ещё раз — это нормально, подпись у новой версии своя.

Там же, в пакете, лежит NSLocalNetworkUsageDescription: начиная с macOS 15 без него игра не увидит серверы и миры в локальной сети.

Сборка своими руками

Нужна, если хочется большего, чем даёт запекание: свои свойства файла, инсталлятор, AppImage, пакет под macOS. Тогда нужны Rust 1.96+ и Python 3 (им скрипт читает название из конфига), а для Windows с Linux — cargo install cargo-xwin и пакеты clang lld llvm (кросс-компиляция, виртуальная машина с Windows не нужна).

Готовые файлы — в client/dist-launcher/. Положите их в launcher/<версия>/ на сервере и выпустите командой launcher publish <версия> — дальше всё как обычно.

--target macos работает только на маке: нужны Xcode (из него берутся lipo и codesign), обе цели Rust — aarch64-apple-darwin и x86_64-apple-darwin, скрипт добавит их сам, — и Go с make generate, им собирается .app. На выходе и готовое приложение, и архив .app.tar.gz для выкладки; пакет сразу подписывается codesign, поэтому игроку хватит «правой кнопкой → Открыть». Кросс-сборки с Linux тут нет и быть не может: подписывает только мак.

Где лаунчер хранит файлы

Папка называется по вашему проекту: при branding.name = «Мир Приключений» сборки и настройки лягут в Мир Приключений внутри системного каталога данных, а не в общую laminara. Благодаря этому два лаунчера разных проектов на одном компьютере не мешают друг другу.

Лаунчеры, собранные прежними версиями, хранили файлы в папке laminara. При первом запуске новый лаунчер сам переносит её под имя проекта — игроку не придётся качать сборку заново.

Что должно быть на компьютере игрока

СистемаЧто нужно доставить
Windows 10 и 11Ничего: рантайм Visual C++ вшит в файл
macOS 10.15 и новееНичего: одно приложение работает и на Apple Silicon, и на Intel
LinuxX11 или Wayland и fontconfig — они есть в любом настольном дистрибутиве

Java игроку ставить не нужно ни на одной из них: нужную версию сервер кладёт в сборку, а лаунчер скачивает её вместе с остальными файлами.

Окно лаунчера рисует процессор, без браузера и без видеодрайвера: открытый лаунчер держит в памяти около 40 МБ, и столько же остаётся, пока идёт игра. Профиль браузера на диске ему тоже не нужен.

Заметка

Файл не подписан сертификатом, поэтому при первом запуске Windows покажет предупреждение SmartScreen. Убирается это только покупкой сертификата подписи кода — и подписывать надо каждую новую версию. Про первый запуск на маке написано выше.

Когда лаунчер надо пересобрать

Пересборка нужна, только если поменялось запечённое:

ПоменялосьНужна пересборка
Адрес сервера, доменДа
Кольцо ключей подписиДа
Соль машинного отпечаткаДа
Брендинг: имя, логотип, ссылка на сайтДа
Сборки, моды, версииНет
Новости, доступ к сборкам, баныНет

Осторожно

Пересобрали ради нового ключа — сначала добавьте его в доверенные, выложите лаунчер, и только потом начинайте им подписывать. Порядок разобран в ключах подписи.
