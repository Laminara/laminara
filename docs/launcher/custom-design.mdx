Цвета, логотип и фон меняются [брендингом](/reference/config#branding) без сборки. Когда
проекту нужен свой дизайн целиком — другая вёрстка экранов, свои шрифты и анимации, — лаунчер
собирается с отдельным **скином**. Вход, загрузка сборок, запуск игры и консоль остаются
общими, поэтому каждое исправление Laminara доходит и до лаунчера со своим дизайном.

## Как это устроено

Интерфейс лаунчера разделён на две части:

- **шов** (`client/launcher/contract`) — данные, которые лаунчер отдаёт интерфейсу, и действия,
  которые интерфейс может вызвать: глобалы `Store`, `Media`, `Theme`, `ConsoleStore`, `LogPick`;
- **скин** — файлы `.slint`, из которых нарисованы экраны. Стандартный лежит в
  `client/launcher/skins/default`.

Скин подключает шов как `@laminara/contract.slint`, а готовые экраны и элементы стандартного
скина — как `@laminara-default/…`. Поэтому можно переопределить только то, что отличается.
Главный файл скина — `main.slint`. Он экспортирует окна `MainWindow` и `ConsoleWindow` и
весь шов одной строкой:

```slint
export * from "@laminara/contract.slint";
```

Скин из одной строки `export * from "@laminara-default/main.slint";` — это стандартный
лаунчер. С него и начинают.

## Репозиторий скина

Каждый скин живёт в своём репозитории, обычно закрытом. Заготовка — `deploy/skin-repo` в
репозитории Laminara: папка `skin` и workflow, который:

- раз в час проверяет, вышел ли новый релиз Laminara, и, если для него ещё нет шаблонов,
  собирает лаунчер со скином под Windows, Linux и macOS и выпускает их релизом с тем же
  тегом;
- собирает скин на каждый пуш, чтобы ошибка в вёрстке не доехала до релиза;
- раз в сутки собирает скин на свежем `main` Laminara — так ломающее изменение шва видно
  заранее, а не в день релиза.

Сама сборка — общий workflow `launcher.yml` из репозитория Laminara, тот же, которым
собирается стандартный лаунчер. Отдельного кода сборки в репозитории скина нет.

<Aside type="note">
Изменения скина выходят вместе со следующим релизом Laminara: сервер берёт шаблон по тегу
своей версии и держит его в кеше. Срочную правку дизайна выпускают патч-релизом Laminara.
</Aside>

## Сервер проекта

<Steps>

1. Выпустите токен GitHub только на чтение содержимого репозитория скина.

2. Укажите репозиторий и токен в блоке `launcher` конфига:

   ```json
   "launcher": {
     "templates": {
       "repo": "Laminara/launcher-myproject",
       "token": "github_pat_…"
     }
   }
   ```

3. Соберите лаунчер, как обычно: `launcher build`. Сервер возьмёт шаблон из релиза
   репозитория скина с тем же тегом, что и его версия, и запечёт в него конфиг.

</Steps>

Дальше всё как у стандартного лаунчера: после `laminara-server update` лаунчер
пересобирается сам (`launcher.autoBake`), а игроки получают новую версию самообновлением.

## Проверка вида

Пример `showcase` собирает экраны на тестовых данных без сервера и сохраняет снимки:

```sh
cd client
LAMINARA_SKIN_DIR=/путь/к/скину cargo run -p laminara --example showcase -- home home.png
```

`LAMINARA_SKIN_DIR` указывает папку с `main.slint`; без неё собирается стандартный скин.
