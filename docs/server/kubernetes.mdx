Сервер работает одной репликой. Профили, ключи подписи, база компьютеров, аккаунты и
настройки веб-консоли сохраняются на постоянном томе. Обновление через `Recreate`
останавливает старый Pod перед запуском нового; на это время сервер недоступен.
Несколько реплик и HPA не поддерживаются.

## Образ

Из корня репозитория:

```sh
docker build -f deploy/Dockerfile --build-arg VERSION="$(cat VERSION)" -t laminara:local .
docker run --rm laminara:local version
```

Dockerfile сам генерирует protobuf и учитывает локальный Go SDK. Образ запускается от
UID `10001`, содержит сертификаты CA и команду `health`; curl внутри не требуется.
Workflow «Контейнер» публикует образ в GHCR только после ручного запуска. Проверка
контейнера на pull request ничего не публикует.

## Helm

Чарт находится в `deploy/helm/laminara`. После публикации нужного образа:

```sh
helm lint deploy/helm/laminara --set-string image.tag="$(cat VERSION)"
helm upgrade --install launcher deploy/helm/laminara \
  --set-string image.tag="$(cat VERSION)" \
  --namespace laminara --create-namespace
```

Версия образа задаётся явно через `image.tag` из `VERSION`, единого источника версии
сервера. Для воспроизводимого развёртывания задайте `image.digest=sha256:...`. Для уже созданного
тома используется `persistence.existingClaim`; иначе чарт создаст PVC на 20 GiB.
При удалении Helm-релиза созданный PVC сохраняется. Прежде чем удалить том вручную,
сохраните ключи и данные: потеря ключа подписи нарушит доверие существующих лаунчеров.

По умолчанию создаётся пустой файл аккаунтов. Аккаунты добавляются через административную
консоль. Для SQL или внешнего источника задайте `bootstrapUsersFile: false`.
Сессии в памяти теряются после перезапуска; для сохранения входов используйте внешний Redis
в `config.auth.sessions`. Чарт не разворачивает базы данных.

`existingConfigSecret` принимает имя Secret с ключом `config.json`. Без него конфиг берётся
из `values.config` и хранится в ConfigMap. Секреты не следует записывать непосредственно
в values: используйте ссылки на окружение или файлы. Внешний Secret монтируется каталогом;
после его обновления перезапустите Pod. Изменение values автоматически меняет checksum Pod.

Слушатель в конфиге должен быть `0.0.0.0:8099`. Service остаётся внутренним (`ClusterIP`).
Ingress включается через `ingress.enabled`, `host`, `className` и `tlsSecret`.
`api.xAccel` выключен: Ingress не получает прямого доступа к файлам Pod.

Контейнер использует файловую систему только для чтения, кроме PVC, `/tmp` и каталога
Unix-сокета. Режим `--config-mode external` блокирует изменение смонтированного конфига
из TUI. Для первичного управления можно выполнить `kubectl exec -it` и открыть
`laminara-server console` внутри Pod.

## Секреты и S3

Строковое значение `"${env:VARIABLE}"` берётся из окружения, а `"${file:/path/to/secret}"`
из файла. Относительный путь разрешается от каталога конфига. Подстановка применяется
к целому значению и не меняет исходный JSON. Отсутствующая переменная или файл останавливают
запуск с ошибкой. В конце файлового секрета убираются переводы строк.

В Helm доступны `env`, `envFrom`, `extraVolumes` и `extraVolumeMounts`. Для S3 при отсутствии
явных ключей используются окружение AWS/MinIO, AWS credentials file, затем IAM.
Поддерживаются временный `sessionToken` и web identity для роли Pod. Для роли настройте
аннотации ServiceAccount и окружение согласно вашему облаку. Явные ключи имеют приоритет.

## Готовность и журналы

`/healthz` сообщает о работающем процессе. `/readyz` проверяет каталог публикаций,
хранилище, SQL или файл аккаунтов, SQL компьютеров и Redis сессий и ограничения запросов,
когда они настроены. Для HTTP-аутентификации и провайдеров внешних модулей отдельной
проверки готовности пока нет. Внешний ответ перечисляет только имена неисправных подсистем.

```sh
laminara-server health --url http://127.0.0.1:8099
```

`log.format` принимает `text` или `json`, `log.level` — `debug`, `info`, `warn`, `error`.
При `api.metrics: true` открывается `/metrics`: время работы, память, число goroutine,
число и суммарное время HTTP-запросов и команд, счётчики ошибок. Имена команд, URL,
аргументы и токены не используются как labels. Доступ к метрикам ограничивается сетевой политикой
или правилами прокси. По умолчанию endpoint выключен.

## Обновление и восстановление

Перед обновлением сохраните конфигурацию и данные PVC, включая `signing.key`, профили,
историю публикаций и файловое хранилище. Для согласованной копии остановите запись:
масштабируйте Deployment до нуля и снимите snapshot средствами вашего CSI либо скопируйте
том через отдельный Pod. SQL, Redis и S3 резервируются отдельно средствами этих сервисов.
Проверьте восстановление на отдельном томе до удаления исходного.

```sh
helm upgrade launcher deploy/helm/laminara --namespace laminara \
  --reuse-values --set-string image.tag=VERSION --wait
helm history launcher --namespace laminara
helm rollback launcher REVISION --namespace laminara --wait
```

Helm rollback возвращает образ и конфигурацию Deployment. Данные PVC он не откатывает;
при несовместимом изменении формата данных понадобится соответствующая резервная копия.
Откат игровой публикации выполняется отдельно через `build-rollback`.

Для удалённого CLI включите `adminService.enabled`, задайте `config.admin.addr` с тем же
портом, смонтируйте TLS-сертификат и ключ через `extraVolumes`/`extraVolumeMounts`.
Административный Service остаётся внутренним; подключение и права токенов описаны
в [удалённом администрировании](/server/administration/).
