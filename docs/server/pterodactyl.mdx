Если серверы у вас живут в Pterodactyl, Laminara ставится туда как обычная игра — через egg. Панель сама скачает бинарь нужной архитектуры, создаст конфиг и первый аккаунт, а консоль панели будет принимать команды сервера: `install`, `publish`, `builds`, `players`, `help`.

Egg лежит в репозитории: [`deploy/pterodactyl/egg-laminara.json`](https://github.com/MrLeonardosMi/Laminara/blob/main/deploy/pterodactyl/egg-laminara.json). Pelican импортирует тот же файл — формат egg у панелей общий.

## Установка

<Steps>

1. Скачайте `egg-laminara.json` из репозитория.

2. В панели: **Nests → Import Egg** (в Pelican — **Eggs → Import Egg**) и выберите этот файл.

3. Создайте сервер на этом egg. Порт нужен один — по нему лаунчер ходит на сервер, на нём же работает вход в игре.

4. Дождитесь конца установки и откройте журнал: установщик печатает логин и пароль первого аккаунта.

</Steps>

<Aside type="note">
Порт из панели попадает в `api.addr` при каждом запуске: панель правит `config.json` сама. Остальное в этом файле — ваше, установщик его не перезаписывает, а при переустановке сервера конфиг и данные остаются на месте.
</Aside>

## Переменные

| Переменная | По умолчанию | Что значит |
| --- | --- | --- |
| Версия | `latest` | `latest` — последний релиз, либо номер вида `1.2.0`. Чтобы обновиться, поменяйте и переустановите сервер в панели |
| Логин администратора | `admin` | Аккаунт создаётся при установке, если `config.json` ещё нет |
| Пароль администратора | пусто | Пустое поле — установщик придумает пароль и напечатает его в журнале |

## Консоль панели

Сервер читает команды со стандартного ввода, поэтому консоль панели работает как встроенная консоль Laminara — только без интерактивных экранов:

```
install survival 1.21.1 loader=neoforge
publish survival
builds
players
```

Кнопка **Stop** посылает `^C`; сервер завершает работу штатно — дописывает журнал и закрывает соединения. Строка готовности для панели — `laminara-server started`.

## Что учесть

- **Только Linux-узлы, x86_64 или arm64.** Образ — `ghcr.io/pterodactyl/yolks:debian` (для Pelican в egg есть вариант `ghcr.io/pelican-eggs/yolks:debian`). Alpine не подойдёт: сервер запускает скачанную Java для установщиков Forge и NeoForge, а ей нужен glibc.
- **Место на диске.** Сборка с модами — это профиль плюс объекты в CAS: несколько гигабайт на сборку, и они растут с каждой публикацией.
- **HTTPS.** Egg поднимает голый HTTP на выданном порту. Домен и сертификат делаются снаружи — прокси узла или отдельный nginx перед сервером. Лаунчер можно собрать и на `http://адрес:порт`, но с доменом обновлять сборки спокойнее: адрес зашит в лаунчер и меняется только пересборкой.
- **Скины.** По умолчанию в конфиге стоит шаблон `https://minotar.net/skin/%nickname%` — чтобы вход в игре заработал сразу. Свои скины настраиваются в блоке `yggdrasil`.
- **Сессии в памяти.** После перезапуска игроки логинятся заново. Нужен Redis — пропишите его в `auth.sessions`.
- **Лаунчер для игроков** собирается не в панели: возьмите `client-config` и соберите его на машине с Rust и pnpm.
